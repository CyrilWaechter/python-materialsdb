# v0.4.0

Material updates (detect, report, opt-in refresh) and a complete colour-scheme
layer: named palettes, a Settings page, and repainting the open model.

## Material updates

- **Pushed materials are fingerprinted.** The identity pset gains
  `fingerprint` (sha256 of the stored material definition) and
  `fingerprint_scheme`; the add-on reports the model's material map back to the
  GUI, so the picker shows each material's live model status (`changed`,
  `gone`, legacy `unknown`) with a change report old → new.
- **Never silently auto-updated.** A changed material is flagged in the picker;
  you choose **Update** (in place — same entity, psets/name/category refreshed,
  layer thicknesses never overwritten), **Replace** (per layer or whole
  material, superseded entities removed) or leave it.
- **Force update used materials.** One button refreshes every materialsdb
  material used by walls/slabs/roofs regardless of its fingerprint state.
- **Construction pushes carry the full per-layer data** (identity, resolved
  psets, `materialsdb.org_layer`, style), and construction layers resolve to a
  store layer by thickness with a shared micrometre tolerance — IFC float noise
  no longer picks the wrong layer. Ambiguous layers offer candidates instead of
  guessing; λ is reported, not matched.

## Colour schemes and palettes

- **Named palettes.** The built-in Lesosai palette stays read-only; custom
  palettes live in `schemes.json` next to `config.json`. The active scheme and
  an *always use category colours* switch (ignore producer colours) are
  preferences, honoured by picker pushes, constructions, project libraries and
  batch exports alike.
- **Standalone Settings page.** Language/country, scheme selector, the
  producer-colour override, model targeting, and a palette editor: all 17
  category colours with pickers, live chips and a sample wall preview,
  save / save-as / rename-on-save / delete, and JSON export/import through the
  browser save dialog.
- **Apply colours to model.** A style-only restyle of every materialsdb
  material in the open Bonsai model (choose the target model, see the listener
  result), keeping foreign/manual styles. Changing a palette no longer needs a
  model re-import.

## Bonsai viewport fixes

- Re-used surface styles are recoloured in place, so a palette change shows on
  the next push instead of keeping the old RGB.
- A material switched to a different style entity now repoints loaded Blender
  objects (Bonsai copies the style's material into mesh slots at load time).
- A construction push reloads the existing instances of its types from IFC, so
  rebuilt layer sets repaint instead of keeping the pre-push materials.

## Picker and GUI fixes

- Facet filters actually filter: clicks inside the dropdown no longer bubble
  into the header sort. The chevron has a proper hitbox, *clear* sits in a
  sticky popover header (disabled when empty), and filtered columns are
  highlighted.
- Materials without a name in the configured language now fall back to a
  language-less name, then English, then the first available one.
- Windows/VSCode: the add-on starts the GUI server with a neutral cwd and
  sanitised environment (no more stale `-m` resolution or inherited
  `PYTHONHOME`).
