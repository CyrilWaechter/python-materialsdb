# AGENTS.md

Unofficial Python client library for [materialsdb.org](http://www.materialsdb.org) (open building-materials format). PyPI name `python-materialsdb`, import name `materialsdb`. GPLv3+. src-layout under `src/materialsdb/`.

## Commands

```bash
pip install -e ".[ifc]"   # dev install; lxml core, ifcopenshell via extra
pip install -e ".[dev]"   # dev tools: pytest, pytest-benchmark, ruff, ty
python3 -m pytest -p no:pytest-blender -q   # full suite; testpaths set in pyproject.toml
python3 -m pytest -p no:pytest-blender tests/test_serialiser.py   # single file
ruff check --exclude src/materialsdb/classes.py src tests dev_utils examples   # lint
ruff format --exclude src/materialsdb/classes.py .                              # format
ty check --project .                                                            # type check
```

- Formatter/linter is **ruff** (NOT black), line-length 120.
- Local pytest needs `-p no:pytest-blender`: a globally installed pytest-blender plugin hijacks collection. CI has no such plugin and uses plain `pytest`.
- CI: `.github/workflows/ci.yml` runs ruff check/format, ty, pytest on push/PR.

`ifcopenshell` is optional (`[ifc]` extra) but required by `materialsdb.ifc.project_library` and `tests/test_project_library.py`.

## Generated code — do not hand-edit

- `src/materialsdb/classes.py` is generated from `src/materialsdb/schema/materialsdb103.xsd` by `dev_utils/classes_generator.py`.
  - Quirk: its paths are cwd-relative and hardcoded (`../src/...` input, writes `classes.py` to cwd). Run from `dev_utils/`, then move the output over `src/materialsdb/classes.py`.
  - It is excluded from both ruff and ty (no-drift policy: generated output must never be hand-formatted or annotated).
- `src/materialsdb/ifc/material_psets.json` is regenerated by `dev_utils/update_material_psets_json.py` (needs ifcopenshell; also cwd-relative paths).

## Test quirks

- Both tests read the fixture `example_v103.xml` from the repo root and write artifacts (`test.xml`, `example_v103.ifc`) back into the repo root.
- `example_v103.xml` is **not tracked by git** — on a fresh clone tests fail until you supply it.
- `tests/_stale_materialsdb.disabled` is a symlink to `../src/materialsdb/` kept out of import paths — never restore the original name (`tests/materialsdb`).

## Release / versioning

- Version lives in `pyproject.toml` `[project] version`. Bump it there.
- Publishing is automated: creating a GitHub release triggers `.github/workflows/pypi_publish.yml` (build + upload to PyPI).

## Packaging / schema notes

- Package data ships only `*.json` and `*.xsd` (`[tool.setuptools.package-data]` in pyproject.toml); new bundled files must match or extend that list.
- Active schema target is `schema/materialsdb103.xsd` (`serialiser.get_xml_schema()`); the 102 xsd/dtd are still shipped.
- `store.py` schema v3: `producer_files` stores per-file `ver`/`crd` from the root `<materials>` element; `Report.duplicates` carries cross-producer material-ID collisions.
- `cache.py` downloads producer/index XML from materialsdb.org into `~/.cache/materialsdb` (honors `XDG_CACHE_HOME`/`APPDATA`) — cache-refresh paths require network access.
- Materials data is localized: language/country come from `config.set_lang()/set_country()` (ISO 639-1 / ISO 3166-1 alpha-2 codes).
- Root `.env` documents an alternative dev setup via `PYTHONPATH` pointing at `src/` plus a local IfcOpenShell checkout instead of pip install.
